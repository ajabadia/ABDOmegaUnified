# scripts/ — Tooling

Utilidades de validación y build del proyecto ABDOmegaUnified.

| Script | Propósito | Uso |
|---|---|---|
| `build_wasm.bat` | Compila los 3 módulos WASM (`midi_in`, `midi_trigger`, `omega_lab_monitor`) desde `modules/` con Emscripten (`em++ -s SIDE_MODULE=1`) hacia `web/public/wasm/`. Requiere `em++` en el PATH (activar con `emsdk_env.bat`). | `scripts/build_wasm.bat` |
| `check_bat_parens.mjs` | **Diagnóstico preventivo del bug de `build_wasm.bat` + footgun `::` en bloques**: escanea los `.bat` del proyecto en busca de (1) `)` sin escapar dentro de bloques `if (...)`/`for ... do (...)`/`else (` multilínea que rompen cmd.exe ("No se esperaba X en este momento"), y (2) `::` dentro de bloques parenthesized multilínea (footgun #717 — usar `REM`). Modelo calibrado empíricamente contra cmd.exe real: omite regiones `%...%` y escapes `^x`; excluye los patrones legítimos `) else (` y `) do (`; NO flaggea `::` top-level (headers de sección) ni labels de un colon (`:label`). Fixtures canónicos en `scripts/_bat_test/`. | `node scripts/check_bat_parens.mjs` (exit 0 = sin issues) |
| `check_bat_parens.cmd` | **Guardia pre-arranque (híbrida)**: wrapper `call`-able que envuelve al escáner para launchers que NO pasan por `build_auto.bat`. Comportamiento: si `node` o el escáner faltan → `[WARN]` y continúa (exit 0 — p.ej. `start_synth.bat` lanza un binario nativo sin node); si el escáner detecta issues → `[ERROR]` y aborta (exit 1). Con el argumento `/strict` (usado por `build_auto.bat`): tooling ausente → `[ERROR]` y aborta (exit 1). | `call "%~dp0check_bat_parens.cmd" [/strict]` + `if errorlevel 1 (...)` |
| `wasm-smoke.mjs` | **Smoke test runtime de los 3 `.wasm` regenerados**: compila e instancia cada binario con un importObject PIC (stack/GOT mutables, bases inmutables), ejecuta `__wasm_call_ctors`, extrae el contrato vía `omega_get_contract` (clave `parameters`) y ejercita `omega_init`/`omega_on_midi`/`omega_on_param`/`omega_process`. Nota: valida la validez binaria + superficie de API, NO la relocación completa (el host real es WAMR en C++). | `node scripts/wasm-smoke.mjs` (exit 0 = los 3 OK) |

## Notas

- **`build_wasm.bat` — bug de paréntesis (fix #714)**: el texto `(emsdk)` dentro del bloque `if (...)` cerró el bloque prematuramente en cmd.exe. El escape canónico `^(emsdk^)` + finales CRLF lo resuelven. `check_bat_parens.mjs` detecta esta clase de bug preventivamente.
- **Escáner `check_bat_parens.mjs`**: acepta rutas de archivo opcionales (`node scripts/check_bat_parens.mjs path/to/x.bat`); sin argumentos escanea todos los `.bat` del repo (excluye `node_modules`, `JUCE`, `build`, `.next`, `.git`, plantillas Squish de CMake y `_bat_test/`).
- **Fixtures de test en `scripts/_bat_test/`** (#720): `colond_in_block.bat` (debe flaggear `::` en bloque, exit 1), `colond_top_level.bat` / `label_in_block.bat` / `rem_in_block.bat` (no deben flaggear, exit 0). `_bat_test/` está excluido del scan de repo para no ensuciar el conteo.
- **`build_auto.bat` integra la guardia como paso 0 (fail-fast) vía `call ... /strict`** (#716 → #718): delega en `check_bat_parens.cmd` con el modo estricto, que aborta también si falta `node` o el escáner. Así `build_auto.bat` ya NO duplica el bloque inline (DRY — un solo punto de invocación del escáner).
- **Launchers que no pasan por `build_auto.bat`** integran la guardia vía `check_bat_parens.cmd` como pre-arranque (#718): `start.bat`, `start_synth.bat` (root → `call "%~dp0scripts\check_bat_parens.cmd"`) y `web/start.bat` (web → `call "%~dp0..\scripts\check_bat_parens.cmd"`), seguidos de `if errorlevel 1 (... exit /b 1)` (modo híbrido: tooling ausente → warn y continúa).
- **Convención de comentarios en `.bat`**: dentro de bloques parenthesized usar `REM` (forma canónica segura), no `::` — el footgun de `::` dentro de bloques es sutil (interacción con `goto`/re-parseo de labels). A nivel top-level ambas formas son válidas (#717). **El escáner lo automatiza** (#720): cualquier `::` dentro de un bloque multilínea se flaggea como issue y hace fallar build_auto.bat (paso 0) y los launchers.
- **Nota de cobertura**: `check_bat_parens.mjs` solo escanea `.bat` — el helper `check_bat_parens.cmd` (`.cmd`) queda fuera del diagnóstico automático. Mantenerlo libre de `)` sin escapar en mensajes dentro de bloques (está validado empíricamente).
- **Line endings**: los `.bat`/`.cmd` del proyecto usan **CRLF** (convención Windows, fix #714). El `.gitattributes` de la raíz fija `*.bat text eol=crlf` y `*.cmd text eol=crlf`; con `core.autocrlf=true` el repo almacena LF y el checkout produce CRLF (#719).
- Ambos `.mjs` son standalone (solo Node estándar, sin dependencias).
